* Overview

Blade is a macOS terminal process viewer written in Zig. It displays running
processes in a hierarchical tree with live CPU and memory metrics, supporting
search, sorting, expansion/collapse, and process signaling (kill).

The application follows a *producer-consumer* architecture with two threads:

- *Producer thread* — collects process snapshots from the OS every 3 seconds
- *Main thread* — processes batches, handles keyboard input, and renders the TUI

Communication between threads uses a lock-free single-producer single-consumer
(SPSC) queue with a capacity of 4 batches.

A =(pid, start_time_ns)= pair that *uniquely identifies a process* even across
PID reuse. Two processes that share the same PID but started at different times
are considered distinct. This is used as the key in the =expanded_pids= hash map
so that expansion state survives view rebuilds.

*** Proc (Raw OS Data)

#+BEGIN_SRC zig
pub const Proc = struct {
    pid: pid_t = 0,
    ppid: pid_t = 0,
    start_time_ns: i128 = 0,
    s_name: [256:0]u8,       // null-terminated process name
    path: [4096]u8,          // binary path on disk
    mem_rss: u64 = 0,        // resident set size in bytes

#+END_SRC

Raw data collected from macOS =libproc= calls. Uses *fixed-size inline arrays*
to avoid heap allocation in the platform layer. The producer packs one =Proc= per
PID into a hash map that becomes part of a =Batch=.

*** Hot/Cold Data Split

The store separates process data into two categories optimized for different
access patterns.

*ProcHot* — fields that change every collection cycle:

#+BEGIN_SRC zig
pub const ProcHot = struct {
    pid: std.posix.pid_t,
    start_time_ns: i128,
    cpu_percent: f32,
    mem_rss: u64,
};
pub const ProcHotList = std.MultiArrayList(ProcHot);
#+END_SRC

=ProcHotList= is a *struct-of-arrays* (SoA) layout. When sorting by CPU, only the
=cpu_percent= slice is touched, keeping the working set small and cache-friendly.

*ProcCold* — fields that are static for the lifetime of a process:

#+BEGIN_SRC zig
pub const ProcCold = struct {
    name: []const u8,         // display name
    path: []const u8,         // binary path
    ppid: std.posix.pid_t,    // parent PID
    name_lower: []const u8,   // lowercase for case-insensitive search
    path_lower: []const u8,   // lowercase for case-insensitive search
};
#+END_SRC

Cold data is read during rendering and searching but never mutated after initial
population.

*** VisibleNode (Tree Rendering)

#+BEGIN_SRC zig
pub const VisibleNode = struct {
    data_idx: u32,        // index into hot[] and cold[]
    depth: u16,           // nesting level (0 = root)
    has_children: bool,
    is_last: bool,        // last sibling at this depth
    is_expanded: bool,    // whether children are visible
};
#+END_SRC

Each visible row in the terminal maps to one =VisibleNode=. The =data_idx= field
is an indirection into the parallel hot/cold arrays. The =depth= field drives
indentation during rendering (2 spaces per level).

=VisibleNode= is an *internal* type used within the Store pipeline. External
consumers (render.zig, event.zig, state.zig) access the materialized
=RenderRow= buffer instead.

*** RenderRow (Render-Ready AoS Buffer)

#+BEGIN_SRC zig
pub const RenderRow = struct {
    pid: pid_t,
    cpu_percent: f32,
    mem_rss: u64,
    name: []const u8,
    path: []const u8,
    depth: u16,
    has_children: bool,
    is_expanded: bool,
    data_idx: u32,
};
#+END_SRC

=RenderRow= is a *materialized, layout-agnostic view* of one visible process
row. It is the output of the SHAPES-inspired layout boundary: the pipeline
operates in SoA (hot/cold MultiArrayList) for computation, then materializes
into AoS (=RenderRow[]=) for consumption.

*Design rationale (SHAPES paper):*
- SoA is optimal for bulk operations (sort by CPU touches only the =cpu_percent=
  slice, tree-building touches only =ppid=)
- AoS is optimal for per-item access (rendering reads all fields of each
  visible row sequentially)
- The =materializeRenderRows()= function is the layout boundary between these
  two worlds

*Ownership:* The =render_rows= backing array is allocated from GPA via
=ArrayListUnmanaged=. The =name= and =path= slices within each =RenderRow=
point into the batch arena (same cross-allocator pattern as =ProcCold=).

*Consumers:*
| Module      | Fields Used                              | Purpose                |
|-------------+------------------------------------------+------------------------|
| render.zig  | All display fields (pid, cpu, mem, name, path, depth, has_children, is_expanded) | Drawing rows |
| event.zig   | pid                                      | Kill signal target     |
| state.zig   | len, has_children, data_idx, pid         | Bounds, expansion, identity |

The =data_idx= field preserves the internal array index so that mutation
operations (expand/collapse) can still map back to the Store's internal
structures without requiring render.zig to know about SoA layout.

** procs/tree.zig — Adjacency (Compressed Sparse Row)

#+BEGIN_SRC zig
pub const Adjacency = struct {
    offsets: std.ArrayListUnmanaged(u32) = .empty,  // length = N + 1
    flat: std.ArrayListUnmanaged(u32) = .empty,     // concatenated child indices

    pub fn childrenOf(self: *const Adjacency, idx: usize) []const u32 {
        const start: usize = @intCast(self.offsets.items[idx]);
        const end: usize   = @intCast(self.offsets.items[idx + 1]);
        return self.flat.items[start..end];
    }
};
#+END_SRC

The parent→child relationship is stored in *Compressed Sparse Row (CSR)* format.
For N processes, =offsets= has N+1 entries and =flat= contains all child indices
concatenated.

Example with 5 processes:

#+BEGIN_SRC
Process indices:  [0, 1, 2, 3, 4]
Children:
  0 → [1, 2]
  1 → [3]
  2 → []
  3 → [4]
  4 → []

offsets: [0, 2, 3, 3, 4, 4]
flat:    [1, 2, 3, 4]

childrenOf(0) → flat[0..2] → [1, 2]
childrenOf(1) → flat[2..3] → [3]
childrenOf(2) → flat[3..3] → []
childrenOf(3) → flat[3..4] → [4]
childrenOf(4) → flat[4..4] → []
#+END_SRC

This representation uses O(N) memory and provides O(1) child lookup, far more
efficient than a hash map of ArrayLists for tree traversal.

** thread/channel.zig — Batch

#+BEGIN_SRC zig
pub const Batch = struct {
    arena: std.heap.ArenaAllocator,
    map: std.AutoHashMap(platform.pid_t, platform.Proc),
    timestamp_ns: i128 = 0,

    pub fn deinit(self: *Batch) void {
        self.arena.deinit();
    }
};

pub const BatchQueue = spsc.SpscQueue(Batch, false);
#+END_SRC

A =Batch= is a self-contained snapshot of all running processes at a point in
time. The =arena= owns all memory used by the =map= (including its internal hash
table storage). On =deinit=, only =arena.deinit()= is called — =map.deinit()= is
intentionally *not called* because the map's backing storage lives inside the
arena. Calling it would attempt to free through a stale allocator pointer.

* Program Flow

** Startup Sequence (main.zig)

#+BEGIN_SRC zig
pub fn main() !void {
    // 1. Create allocator
    var gpa = std.heap.GeneralPurposeAllocator(.{}){};
    const gpa_alloc = gpa.allocator();

    // 2. Initialize terminal backend
    var backend = try tui.backend.AnsiBackend.init(gpa_alloc);
    var terminal = try tui.terminal.Terminal.init(gpa_alloc, backend.interface());
    try terminal.hideCursor();

    // 3. Create application state and batch queue
    var app = state.AppState.init(gpa_alloc);
    var queue = try channel.initQueue(gpa_alloc);

    // 4. Thread synchronization
    var mutex: std.Thread.Mutex = .{};
    var condition: std.Thread.Condition = .{};
    var thread_running = std.atomic.Value(bool).init(true);

    // 5. Spawn producer thread
    const handle = try std.Thread.spawn(.{}, producer.run, .{thread_args});

    // 6. Enter main event loop
    while (app.running) { ... }

    // 7. Signal producer to stop, join thread
    thread_running.store(false, .release);
    condition.signal();
    handle.join();
}
#+END_SRC

** Producer Thread (thread/producer.zig)

#+BEGIN_SRC zig
pub fn run(args: ThreadArgs) void {
    while (args.running.load(.acquire)) {
        fetchAndSend(args.queue, args.running) catch |err| {
            std.debug.print("Producer Error: {}\n", .{err});
        };
        // Sleep 3 seconds (interruptible via condition variable)
        args.condition.timedWait(args.mutex, poll_interval_ns);
    }
}

fn fetchAndSend(queue: *channel.BatchQueue, running: ...) !void {
    var batch_arena = std.heap.ArenaAllocator.init(std.heap.page_allocator);
    const arena_alloc = batch_arena.allocator();
    const map = try platform.collectSnapshot(arena_alloc);
    const timestamp = std.time.nanoTimestamp();

    var batch = channel.Batch{
        .arena = batch_arena,  // ownership moves into batch
        .map = map,
        .timestamp_ns = timestamp,
    };

    // Push with exponential backoff
    var backoff_ns: u64 = 100_000;
    while (!queue.tryPush(batch)) {
        if (!running.load(.acquire)) { batch.deinit(); return; }
        std.Thread.sleep(backoff_ns);
        backoff_ns = @min(backoff_ns * 2, 10 * std.time.ns_per_ms);
    }
}
#+END_SRC

The producer:
1. Allocates a fresh =ArenaAllocator= backed by =page_allocator=
2. Calls =platform.collectSnapshot()= to enumerate all processes
3. Wraps the result in a =Batch= (arena ownership transfers to the batch)
4. Pushes the batch onto the SPSC queue with exponential backoff
5. Sleeps for 3 seconds (interruptible for clean shutdown)

** Data Pipeline (procs/store.zig)

When a new batch arrives, =buildPipeline= runs:

#+BEGIN_SRC
buildPipeline(search)
  │
  ├─ populateView()
  │   ├─ Clear hot[] and cold[]
  │   ├─ For each process in current_batch.map:
  │   │   ├─ Calculate CPU delta:
  │   │   │   cpu% = (new_total - old_total) / time_delta × 100
  │   │   ├─ Append to hot[]: { pid, start_time, cpu%, mem_rss }
  │   │   └─ Append to cold[]: { name, path, ppid, name_lower, path_lower }
  │   └─ Free previous_batch arena
  │
  ├─ buildPidIndexMap(hot.items(.pid))
  │   └─ HashMap: pid → array index
  │
  ├─ buildAdjacency(cold, pid_to_index, N)
  │   ├─ Count children per parent
  │   ├─ Compute cumulative offsets
  │   └─ Fill flat[] with child indices
  │
  ├─ sortChildren(adjacency, sort_context)
  │   └─ Sort each parent's children slice in flat[]
  │
  ├─ rebuildVisible(search)
  │   └─ buildVisibleNodes(hot, cold, adj, expanded_pids, search)
  │       ├─ Find roots (processes with no parent in the set)
  │       ├─ If searching: mark matching nodes + ancestors
  │       └─ DFS traversal → VisibleNode[]
  │
  └─ materializeRenderRows()                    ← SHAPES layout boundary
      ├─ Clear render_rows, ensureTotalCapacity
      ├─ For each VisibleNode:
      │   └─ Flatten hot[data_idx] + cold[data_idx] + tree info → RenderRow
      └─ Output: render_rows[] (AoS, contiguous, render-ready)
#+END_SRC

The =materializeRenderRows()= step is the *SHAPES layout boundary*. Everything
above operates in SoA layout (MultiArrayList, separate cold ArrayList).
Everything below (render, event, state UI logic) operates in AoS layout
(=RenderRow[]=). This decouples the renderer from the internal data layout —
changing the hot/cold split requires updating only =materializeRenderRows()=,
not =render.zig=.

** CPU Percentage Calculation

CPU usage is computed as a delta between consecutive snapshots:

#+BEGIN_SRC zig
// In populateView():
const prev_cpu = previous_batch.map.get(pid).total_user + total_system;
const curr_cpu = current_batch.map.get(pid).total_user + total_system;
const cpu_delta = curr_cpu - prev_cpu;
const time_delta = current_batch.timestamp_ns - previous_batch.timestamp_ns;
const cpu_percent = @as(f32, @floatFromInt(cpu_delta)) /
                    @as(f32, @floatFromInt(time_delta)) * 100.0;
#+END_SRC

This gives per-process CPU usage as a percentage of *one core*. A process using
two cores fully would show 200%.

fn executeAction(app: *state.AppState, action: keymap.Action) void {
    switch (action) {
        .show_help    => showHelp(app),
        .move_up      => app.up(),
        .move_down    => app.down(),
        .page_up      => for (0..5) |_| app.up(),

        .start_search => app.mode = .search_edit,

        .kill_force   => killSelected(app, true),    // SIGKILL
        .sort_by_pid  => app.setSort(.pid),
        .sort_by_name => app.setSort(.name),
        .sort_by_cpu  => app.setSort(.cpu),
        .sort_by_mem  => app.setSort(.mem),
        .toggle_expand     => app.toggleSelectedExpansion(),
        .toggle_expand_all => app.toggleExpandAll(),
        .exit_search_view  => { app.search_len = 0; app.refreshFilter(); app.mode = .normal; },

}

** Tree Prefix Rendering

Each row in the process list is indented according to its =depth= and annotated
with an expansion glyph:

#+BEGIN_SRC
Process list output:

1234    launchd           0.0%    12.3 MB  /sbin/launchd
  v     logd              0.1%     8.1 MB  /usr/libexec/logd
    >   sub_process       0.0%     2.0 MB  /usr/libexec/sub
  v     configd           0.0%     4.5 MB  /usr/libexec/configd

Legend:
  v  = expanded (has children, showing them)
  >  = collapsed (has children, hiding them)
     = leaf node (no children)
  Indentation = 2 spaces per depth level
#+END_SRC

#+BEGIN_SRC zig
fn renderTreePrefix(buf, x, y, row: model.RenderRow, style, max_width) u16 {
    var prefix_buf: [64]u8 = undefined;
    var pos: usize = 0;

    // Indent: 2 spaces per depth level
    var d: u16 = 0;
    while (d < row.depth and pos + 2 < prefix_buf.len) : (d += 1) {
        prefix_buf[pos]     = ' ';
        prefix_buf[pos + 1] = ' ';
        pos += 2;
    }

    // Expansion glyph
    const glyph: u8 = if (row.has_children)
        (if (row.is_expanded) 'v' else '>')
    else ' ';
    if (pos + 2 <= prefix_buf.len) {
        prefix_buf[pos]     = glyph;
        prefix_buf[pos + 1] = ' ';
        pos += 2;
    }

    const width: u16 = @min(max_width, @as(u16, @intCast(pos)));
    if (width > 0) {
        buf.setString(x, y, prefix_buf[0..width], style);
    }
    return width;
}
#+END_SRC

** Hot Data (MultiArrayList) Memory Layout

=ProcHotList= uses =std.MultiArrayList= which stores fields in separate arrays
(struct-of-arrays layout):

#+BEGIN_SRC
Traditional Array of Structs (AoS):
┌───────────────────────────────────────┐
│ pid₀ time₀ cpu₀ mem₀ │ pid₁ time₁ cpu₁ mem₁ │ ...
└───────────────────────────────────────┘
  Cache line touches ALL fields even when sorting by CPU only

MultiArrayList Struct of Arrays (SoA):
┌──────────────────┐
│ pid₀ pid₁ pid₂ pid₃ ... │  ← pid slice
├──────────────────┤
│ time₀ time₁ time₂ ...   │  ← start_time_ns slice
├──────────────────┤
│ cpu₀ cpu₁ cpu₂ cpu₃ ... │  ← cpu_percent slice (4 bytes each)
├──────────────────┤
│ mem₀ mem₁ mem₂ mem₃ ... │  ← mem_rss slice
└──────────────────┘

Access patterns:
  hot.items(.cpu_percent)  → returns []f32 (contiguous in memory)
  hot.items(.pid)          → returns []pid_t (contiguous in memory)

When sorting by CPU: only the cpu_percent slice and pid slice are
touched. The start_time_ns and mem_rss slices stay cold in cache.
#+END_SRC

All four backing arrays are allocated from GPA in a single allocation managed by
=MultiArrayList=. They grow together via =ensureTotalCapacity=.

** Batch Arena Size Estimation

For a system with N processes, each batch arena allocates approximately:

#+BEGIN_SRC
HashMap overhead:
  keys:     N × sizeof(pid_t)           = N × 4 bytes
  values:   N × sizeof(Proc)            = N × 4,600 bytes  (256 + 4096 + fields)
  metadata: N × 1 byte                  = N bytes
  ≈ N × 4,605 bytes

PID enumeration buffer:
  N × sizeof(pid_t)                     = N × 4 bytes
  (freed inline, memory reused by arena)

Derived structures (main thread):
  pid_to_index HashMap: ~N × 12 bytes
  Adjacency offsets:    (N+1) × 4 bytes
  Adjacency flat:       (N-roots) × 4 bytes
  child_counts:         N × 4 bytes
  write_cursor:         N × 4 bytes
  visible_nodes:        N × sizeof(VisibleNode) = N × 12 bytes
  lowercase copies:     ~N × (avg_name + avg_path) bytes

For 500 processes: ~2.5 MB per batch arena
For 1000 processes: ~5 MB per batch arena

At most 2 batches exist simultaneously (current + previous),
so peak batch memory ≈ 10 MB for 1000 processes.
#+END_SRC

* Tree Building Algorithm

The tree is built from a flat list of processes with parent pointers (=ppid=)
into a visible tree of =VisibleNode= entries. This is the most complex algorithm
in the codebase.

** Step 1: Build PID Index Map

#+BEGIN_SRC zig
// tree.zig: buildPidIndexMap
// Input: hot.items(.pid) → slice of all PIDs
// Output: HashMap(pid → index into hot/cold arrays)
fn buildPidIndexMap(pids: []const pid_t, arena: Allocator) !AutoHashMap {
    for (pids, 0..) |pid, i| {
        map.put(pid, @intCast(i));
    }
}
#+END_SRC

** Step 2: Build Adjacency (CSR)

#+BEGIN_SRC zig
// tree.zig: buildAdjacency
// Input: cold items (for ppid), pid_to_index map, N processes
// Output: Adjacency (offsets + flat arrays)

// Phase 1: Count children per parent
for (cold_items) |item| {
    if (pid_to_index.get(item.ppid)) |parent_idx| {
        count[parent_idx] += 1;
    }
}

// Phase 2: Prefix sum → offsets
offsets[0] = 0;
for (0..n) |i| {
    offsets[i+1] = offsets[i] + count[i];
}

// Phase 3: Fill flat array
for (cold_items, 0..) |item, child_idx| {
    if (pid_to_index.get(item.ppid)) |parent_idx| {
        flat[cursor[parent_idx]] = child_idx;
        cursor[parent_idx] += 1;
    }
}
#+END_SRC

** Step 3: Sort Children

Each parent's children slice in =flat[]= is sorted using the active sort column
and direction. This ensures the tree displays children in the user's preferred
order.

** Step 4: Build Visible Nodes (DFS)

#+BEGIN_SRC
buildVisibleNodes(hot, cold, adj, expanded_pids, search)
  │
  ├─ Find roots: processes whose ppid is not in pid_to_index
  │   (i.e., their parent is not in the current snapshot)
  │
  ├─ If search is active:
  │   ├─ For each process, check if name_lower or path_lower
  │   │   contains the search string (case-insensitive)
  │   ├─ Mark matching processes
  │   ├─ Walk ancestors up to root, marking them as "has match in subtree"
  │   └─ These flags determine visibility during DFS
  │
  └─ DFS traversal from each root:
      ├─ Push root onto stack with depth=0
      └─ While stack is not empty:
          ├─ Pop node
          ├─ If searching and node has no matches in subtree → skip
          ├─ Append VisibleNode { data_idx, depth, has_children, is_last, is_expanded }
          ├─ If expanded (or searching with matches in children):
          │   └─ Push children in reverse order (so first child is processed first)
          └─ Continue
#+END_SRC

* Sorting

** Comparison Function

#+BEGIN_SRC zig
// sort.zig
pub fn compareByIndex(ctx: SortContext, a: usize, b: usize) bool {
    const order = switch (ctx.sort_column) {
        .pid  => std.math.order(ctx.pids[a], ctx.pids[b]),
        .cpu  => {
            const cmp = std.math.order(ctx.cpu_percents[a], ctx.cpu_percents[b]);
            if (cmp != .eq) return cmp;
            return std.math.order(ctx.pids[a], ctx.pids[b]);  // tiebreaker
        },
        .mem  => { /* similar with tiebreaker */ },
        .name => { /* string comparison with tiebreaker */ },
        .path => { /* string comparison with tiebreaker */ },
    };
    return if (ctx.sort_direction == .asc) order == .lt else order == .gt;
}
#+END_SRC

Sorting is *stable within siblings*: children of the same parent are sorted
independently, preserving the tree hierarchy. The PID tiebreaker ensures
deterministic ordering when primary sort values are equal.

* Search

Search performs case-insensitive substring matching on process names and paths.

#+BEGIN_SRC
User types "/" → mode = .search_edit
User types characters → appended to search_buf[0..search_len]
  └─ Each keystroke calls refreshFilter()

User presses Esc → mode = .normal (search cleared or preserved)

The search is *live*: each character immediately rebuilds the visible tree. The
lowercase copies (=name_lower=, =path_lower=) in =ProcCold= are pre-computed
during =populateView()= so no allocation occurs during search filtering.

* Threading Model

#+BEGIN_SRC
┌──────────────────┐         SPSC Queue          ┌──────────────────┐
│  Producer Thread │  ═══════(capacity 4)═══════► │   Main Thread    │
│                  │         Lock-free             │                  │
│  Collects process│                               │  Processes batch │
│  snapshots every │                               │  Handles input   │
│  3 seconds       │                               │  Renders UI      │
└──────────────────┘                               └──────────────────┘
     │                                                  │
     │  Shared:                                         │
     ├─ thread_running: atomic bool                     │
     ├─ mutex + condition: for clean shutdown           │

     No shared mutable state beyond these primitives.
     Batch ownership is transferred, never shared.
#+END_SRC

** Safety Properties

- *No data races:* The SPSC queue is lock-free and designed for exactly one
  producer and one consumer. The =thread_running= flag uses atomic operations
  with acquire/release ordering.

- *No dangling pointers:* Arena-based allocation means all batch data is freed
  in one operation. Cold string slices are only valid while =current_batch= is
  alive, and =populateView()= rebuilds them from the new batch before freeing
  the old one.

- *Clean shutdown:* The main thread sets =thread_running= to false, signals the
  condition variable (waking the producer from sleep), and joins the thread.
  Any batch the producer was building is freed via its arena if the push fails.

- *Backpressure:* If the queue is full (main thread is slow), the producer
  retries with exponential backoff (100μs → 10ms cap). It checks
  =thread_running= between retries to support clean shutdown.

* Key Invariants

1. =hot.len == cold.items.len= — always in sync
2. =visible_nodes[i].data_idx < hot.len= — valid index
3. =render_rows.len == visible_nodes.items.len= — materialized 1:1
4. =render_rows[i]= fields correspond to =hot/cold[render_rows[i].data_idx]=
5. =selected_item < render_rows.items.len= — clamped after every rebuild
6. =adjacency.offsets.len == hot.len + 1= — CSR format requirement
7. Expansion state keyed by =ProcIdentity= (survives PID reuse)
8. Previous batch freed only after new batch is fully processed
9. =map.deinit()= never called on batch — arena owns the backing storage

** Binding Resolution

#+BEGIN_SRC zig
pub fn getAction(key: Key, mode: Mode) ?Action {
    for (keymap) |binding| {
        if (std.meta.eql(binding.key, key)) {       // structural equality
            for (binding.modes) |m| {
                if (m == mode) return binding.action;
            }
        }
    }
    return null;
}
#+END_SRC

The first matching binding wins. This means the *order of the keymap array
matters* — earlier entries take priority. For example, Esc maps to =quit= in
normal mode but =exit_search_view= in search_view mode because the bindings
have different =modes= arrays.

* Sort Column Toggle Behavior

When the user presses a sort key (P/N/C/M), the =setSort= function implements
smart toggling:

#+BEGIN_SRC zig
pub fn setSort(self: *Store, column: model.SortColumn) void {
    if (self.sort_column == column) {
        // Same column: toggle direction (desc → asc → desc)
        self.sort_direction = if (self.sort_direction == .asc) .desc else .asc;
    } else {
        // Different column: switch to it, default descending
        self.sort_column = column;
        self.sort_direction = .desc;
    }
}
#+END_SRC

This means pressing =C= once sorts by CPU descending (highest first). Pressing
=C= again reverses to ascending (lowest first). Pressing =M= switches to memory
descending.

* Subtree Expansion Algorithm

** Single Node Toggle

=toggleSelectedExpansion= expands or collapses an *entire subtree*, not just one
level:

#+BEGIN_SRC zig
pub fn setExpandedSubtree(self: *Store, root_idx: u32, expand: bool) !void {
    var stack = std.ArrayListUnmanaged(u32){};
    defer stack.deinit(self.gpa);
    try stack.append(self.gpa, root_idx);

    while (stack.items.len > 0) {
        const node_idx = stack.pop();
        const children = self.adjacency.childrenOf(node_idx);

        if (children.len > 0) {
            const id = self.identityAt(node_idx);
            if (expand) {
                try self.expanded_pids.put(id, {});
            } else {
                _ = self.expanded_pids.remove(id);
            }
            // Push children in reverse for DFS order
            for (children reversed) {
                try stack.append(self.gpa, child);
            }
        }
    }
}
#+END_SRC

This uses an iterative DFS (not recursive) to avoid stack overflow on deeply
nested process trees.

** Toggle All (=*= key)

The toggle-all algorithm uses a "smart" heuristic:

#+BEGIN_SRC
toggleExpandAll():
  1. Scan all processes
  2. Count parent nodes (nodes with children)
  3. Check if ANY parent is collapsed

  If any_collapsed:
    → Expand ALL parents (add to expanded_pids)
  Else (all expanded):
    → Collapse ALL parents (remove from expanded_pids)
#+END_SRC

This provides intuitive behavior: pressing =*= opens everything if anything
is closed, and closes everything only when everything is already open.

* Search Edit Mode: Arrow Key Navigation

While typing a search query (=search_edit= mode), arrow keys still navigate
the process list:

#+BEGIN_SRC zig
fn handleSearchEditMode(app: *state.AppState, key: tui.KeyEvent) void {
    switch (key.code) {
        .char => |c| {
            if (c < 128) {
                app.searchAppend(@intCast(c));
                app.refreshFilter();   // live search on each keystroke
            }
        },
        .backspace => {
            app.searchBackspace();
            app.refreshFilter();
        },
        .enter => app.mode = .search_view,  // cement search results
        .esc => {
            app.searchClear();
            app.refreshFilter();
            app.mode = .normal;
        },
        .up => app.up(),               // navigate while typing
        .down => app.down(),
        else => {},
    }
}
#+END_SRC

This enables a workflow where you can type a search, see results update live,
and immediately navigate to the desired process without pressing Enter first.

* macOS Path Error Handling

When =proc_pidpath()= fails for a process, the path field is set to a
human-readable error label instead of being left empty:

#+BEGIN_SRC zig
if (path_len > 0) {
    // normal path copy
} else {
    const e = std.posix.errno(0);
    if (e == .SRCH) continue;  // process exited, skip entirely
    const err_label: []const u8 = switch (e) {
        .PERM   => "[permission denied]",
        .NOENT  => "[binary deleted]",
        else    => "[path unavailable]",
    };
    @memcpy(proc.path[0..err_label.len], err_label);
    proc.path[err_label.len] = 0;
}
#+END_SRC

This means users see contextual error information in the Path column instead of
blank entries.

* Selection Preservation

Across all view mutations (sort change, search filter, batch arrival), the
application preserves the user's cursor position by identity:

#+BEGIN_SRC
Any view mutation:
  1. prev = getSelectedIdentity()
     └─ Captures (pid, start_time) of selected process
        via render_rows[selected_item].data_idx → identityAt()

  2. Perform mutation (pipeline rebuild, re-sort, etc.)
     └─ visible_nodes + render_rows arrays are rebuilt

  3. restoreAndClamp(prev)
     ├─ restoreSelection(prev)
     │   └─ Linear scan of render_rows for matching identity
     │      └─ If found: selected_item = found index
     └─ Clamp: selected_item = min(selected_item, render_rows.len - 1)
#+END_SRC

Edge case: if =selected_item == 0=, =getSelectedIdentity= returns =null= (no
restoration attempted). This avoids unnecessary scanning when the user hasn't
moved from the top.

* Error Handling Strategy

The codebase uses a layered error handling approach:

** Platform Layer — Per-Process Resilience

Process enumeration never fails wholesale. If =proc_pidinfo= fails for one
process, that process is skipped and the rest continue. Only =proc_listpids=
failure (cannot get PID list at all) returns an error.

** Store Layer — Toast on Failure

All store operations (=buildPipeline=, =sortAndRebuild=, =rebuildVisible=)
propagate errors via =!void=. The =AppState= wrapper catches these errors and
displays them as toast notifications:

#+BEGIN_SRC zig
self.procs.buildPipeline(self.searchSlice()) catch |err| {
    self.showToastFmt("buildView failed: {}", .{err}, .err);
    return;
};
#+END_SRC

The UI continues running even if a rebuild fails — the previous visible state
is preserved.

** Producer Thread — Log and Retry

The producer thread catches all errors from =fetchAndSend= and prints them to
stderr. It then sleeps and tries again on the next cycle:

#+BEGIN_SRC zig
fetchAndSend(args.queue, args.running) catch |err| {
    std.debug.print("Producer Error: {}\n", .{err});
};
#+END_SRC

This means the process viewer stays alive even if one collection cycle fails
(e.g., temporary permission issue).
